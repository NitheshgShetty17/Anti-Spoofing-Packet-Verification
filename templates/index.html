What is Anti-Spoofing?

Spoofing is an attack in which an attacker pretends to be a trusted source by using a fake source address. Anti-spoofing techniques use cryptographic verification to ensure the sender identity in the packet header cannot be falsified.

🔍

What is Packet Verification?

Packet verification checks whether the received packet is authentic and whether its information has been changed. It uses secret-key-based cryptographic hashing and sequence counters to reject tampered or replayed packets.

Section 03 • Step-by-Step Flow

How It Works

The complete 6-step anti-spoofing packet verification lifecycle.

Step 1

Packet Creation

The sender creates a packet containing source IP, destination IP, message and sequence number.

↓
Step 2

Verification Value Generation

A secret key and hash function are used to create a verification value for the packet.

↓
Step 3

Packet Transmission

The packet travels from the sender to the receiver through the network.

↓
Step 4

Authentication and Integrity Check

The receiver calculates the expected verification value and compares it with the received value.

↓
Step 5

Sequence Number Check

The receiver checks whether the sequence number is new. An already-used sequence number indicates a possible replay attack.

↓
Step 6

Final Decision

If authentication, integrity and sequence checks are successful: PACKET ACCEPTED. Otherwise: PACKET REJECTED.

Section 04 • Security Analysis

Attack Cases & Scenarios

Comparative evaluation of genuine traffic against three primary network attack vectors.

Case 1

Genuine Packet

ACCEPTED
What happens: The authorized sender transmits an untampered packet with a new sequence number.
What the attacker changes: None (No attacker intervention).
What the receiver detects: Verification value matches; sequence number is fresh.
Final result: ✓ PACKET ACCEPTED
Case 2

Packet Modification

REJECTED
What happens: The attacker intercepts the packet in transit and alters the message content.
What the attacker changes: Changes message from "Hello Receiver" to "Transfer Rs.50000 to attacker" while keeping original verification value.
What the receiver detects: Computed verification value does not match received value. Integrity check fails.
Final result: ✗ PACKET REJECTED (Reason: Packet information was modified.)
Case 3

IP Spoofing

REJECTED
What happens: Attacker attempts to impersonate an authorized host by forging the Source IP.
What the attacker changes: Changes Source IP from 192.168.1.10 to 10.0.0.99 while keeping original verification value.
What the receiver detects: Source IP is included in verification value generation; mismatch detected. Source identity cannot be verified.
Final result: ✗ PACKET REJECTED (Reason: Source identity could not be verified.)
Case 4

Replay Attack

REJECTED
What happens: Attacker captures a genuine packet and retransmits the same packet again without changes.
What the attacker changes: Nothing. The packet and verification value remain unmodified.
What the receiver detects: Verification value is correct, but sequence number 1001 is already processed and not new.
Final result: ✗ PACKET REJECTED (Reason: Old packet was sent again.)
